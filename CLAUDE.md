# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

The project is **Arxiv Resanity**, a fork of karpathy's arxiv-sanity-lite. Say "the original arxiv-sanity-lite" only when you mean his version.

## Working rules (from the user, keep these)

- Commit on your own after every substantial change, without waiting to be asked. Use a brief title and explain the reasons in the commit body. Don't push; the user reviews and pushes.
- Whenever the user gives guidance or corrects a mistake, add it to this section so it doesn't happen again, and commit that too.
- Git author is `Dorian Koch <do.ko1605.dk@gmail.com>`, set in the repo's local git config.
- Flag evaluation caveats yourself, as soon as you see them, and fix them before drawing conclusions. Don't sit on a concern you noticed. (Example: the arxiv_daemon background papers are newer than every Scholar Inbox rating, so eval scores against them are inflated. Use `eval.py run --pool rated`.)
- Never hammer arXiv; the user does not want to be banned. Every API call goes through `db.arxiv_slot()` with a timeout and bounded backoff (arxiv_daemon.py once retried empty pages every 0.5 s, forever). Pause ≥3s between API calls (harvest_papers.py uses 5s), honor 503 Retry-After, back off on errors, and don't re-download what is already in papers.sqlite. For bulk data, use the Hugging Face snapshot (import_snapshot.py) instead of arXiv's APIs. Pages on arxiv.org itself (`/html`, `/pdf`, `/abs`) fall under its robots.txt, which asks for `Crawl-delay: 15`: fetch them through `db.arxiv_slot(pause=15)`, and never touch the paths it disallows (`/refs`, `/cits`, `/api`, `/search`, ...).
- arXiv calls a user can trigger (`/import`) must go through `db.arxiv_slot()` (one call per 3.5 s across processes) and count against `FETCH_LIMIT_USER`/`FETCH_LIMIT_TOTAL` via the `fetches` table. Never fetch from a GET handler.
- Anything outward-facing (emails, pushes to other services) is off by default and never fires on first start or right after being enabled; the user turns it on after testing. (The digest once defaulted to on and would have mailed everyone before the DNS records existed.)
- Docker networking: all services share the single external network `arxiv-resanity` (docker-compose.override.yml); services and containers are both named `arxiv_resanity_<x>` (web, updater, mail) so nginx can find them and nothing clashes on the shared network, with underscores, not dashes (user preference; the network keeps its dash). (Renaming only `container_name` wasn't what the user asked for.) (A request for "its own network" meant one network for the project, not one per service.)
- EU law (GDPR/ePrivacy): never load anything from a third-party server in pages (vendor it into static/vendor via update_vendor.py; the CSP enforces it), new email addresses go through the double opt-in (`request_email`/`confirm_email`, never store an unconfirmed address as `email`), and keep templates/privacy.html true whenever you change what is stored, logged or sent anywhere.
- UX: the point of the site is the most relevant recent papers, so users with tags land on "For you" (30 days), not "Newest". No page may block for seconds; slow work loads in the background behind a placeholder that says what is happening. Placeholders are skeletons (a blanked copy of the content that is coming, like React Suspense fallbacks), not spinners (user preference). Every option or filter gets a tooltip plus a visible hint (touch screens), but no badges on things that are plainly clickable (the whole thumbnail opens big, no ⤢ mark on it), and every tag needs a visible list of its saved papers.
- Cards stay compact: per-paper information about the user's tags shows the one best tag, not a list of every tag (search results' fit score). The "+ note" control sits in the links row and never makes a card taller; a note, once there, is always shown (cut after a few lines with "show more"; one ellipsized line on compact cards).
- Offline reading is purely a convenience: it must never change what a page gets while there is a network. static/app/sw.js answers from the device only when the server can't be reached or a page's html takes over `SLOW_PAGE` ms (the html is the same app; versioned static files never change under their url); data always comes from the server, and on a slow connection (user request: "just in general for the site") lib.js shows the kept copy of a list after `SLOW_MS`, with a note that says so, until the server's arrives. Don't make anything cache-first for pages or data, and never show a kept copy without that note.
- Offline light copies (static/app/shrink.js) may lose quality but never content: no dropped pages ("dropping pages is no go"), a bad-quality JPEG rather than a gray box, and no font swap that changes a symbol. Going over the 200 kB target is the lesser evil.
- Keep the button row above the paper list short (Share, Cards, Titles only): a Summaries/Abstracts switch added there wrapped badly on phones. Put preferences in the profile, and offer them in context (a link on the card) when the user's behavior suggests one.
- Links that leave the site open in a new tab (static/app/lib.js sets target=_blank on click for every off-site link in the app, so new links there are covered automatically; the few server-rendered pages load no script, so their off-site links carry target=_blank themselves).
- No full page loads on the site's own actions: the site is a client-side app (Preact + htm ES modules, no build step) that talks to Flask over JSON; the user wants it served like a static frontend (nginx or Flask, either is fine). New pages are a `/ui/<page>` endpoint plus a page in static/app, new actions POST endpoints answering JSON; only pages opened from outside (oauth consent, email links, errors of plain form posts) stay server-rendered. Every library is vendored as an ES module (update_vendor.py) and imported through the shell's import map.
- Public profiles (`users.public`, shown as "Public profile", not "sharing"): right after signup, a dialog (base.html, `session['ask_public']`) asks about it with the box ticked; the account stays private until it is answered. That was the user's decision after being told it likely conflicts with Art. 25(2) GDPR (privacy by default) and Planet49 (pre-ticked boxes aren't consent), and asked for a dialog instead of a checkbox on the login form; don't silently flip it back, but don't extend the pattern to other data either.
- AI summaries (model calls cost money): only logged-in users' pages may start them (visitors see the ones that exist; on other cards the Summary tab is grayed out, with a popover on hover or tap saying that nothing is being generated and why, never an inline box), every paper in a digest mail must have one, pages never wait for them (cards show Summary / Abstract tabs: the abstract while the summary is written, its tab grayed out with a light sweeping across, not clickable; which tab cards open on is a profile setting, `users.card_tab`, localStorage for visitors; a card's tabs switch only that card, and after a few switches away from the default the card offers to change it), and calls go out in batches close together in time, so the provider can reuse its prompt cache.
- Papers from sites other than arXiv (ACL Anthology, PMLR, JMLR, CVF, NeurIPS, ISCA) come in one at a time, only when someone asks: a user adds one (`/import`, an agent's save_papers), or clicks a cited one on the graph. Never crawl or bulk-fetch those sites, and never fetch a paper just because a reference names it (the Matcher only keeps its id). Anything that depends on where a paper lives (id format, links, metadata, PDF/HTML urls, year, license, request slot) goes through `aslite/sources.py`; no other code builds a paper site's url or assumes an id is arXiv's. The same paper must never be stored twice: one that is on arXiv too is kept as the arXiv paper (see `fetch_missing` and `merge_twins` below).
- Work and commit directly on `master`; don't create feature branches, even if a pasted prompt asks for one.
- Every change to a table that may already exist needs a migration for existing databases (`ALTER TABLE ... ADD COLUMN` under `BEGIN IMMEDIATE`, see `PapersDB._add_columns`, `RefsDB._migrate`) and a test that opens an old one, even if you think the earlier version was never deployed: the user may have pulled any commit (the server ran `refs.sqlite` from an intermediate commit, and every page broke on a missing column). `CREATE TABLE IF NOT EXISTS` never changes an existing table. Lookups that only decorate a page (thumbnails, counts on tabs) catch their errors, so a broken side database can't take the page down.

## Commands

The shell is zsh, which doesn't word-split an unquoted `$VAR`. A command stored in a variable has to be expanded as `${=VAR}`, and a list of ids should be looped over as an array (`for p in ${=P}`). A failed split often shows up only as an empty log.

Never gate a commit on `uv run pytest | tail -1 && git commit`: the pipe returns `tail`'s exit code, so a failing run still commits. Use `uv run pytest -q && git commit ...`, or `setopt pipefail` first.


Dependencies are managed with uv (`pyproject.toml` + `uv.lock`, Python 3.12+, `package = false`). Every script runs from the repo root, because paths such as `data/` and `secret_key.txt` are relative to it.

```bash

                                           # (uv sync drops extras you don't list, so pass every one you need)
uv run pytest                              # smoke tests, synthetic corpus in a temp dir, no network
uv run ruff check . && uv run ruff format . # lint (bug-finding rules) + format; run both before committing
uv run pytest tests/test_rank.py -k logreg # single test

uv run python arxiv_daemon.py --num 2000   # pull new papers from the arxiv API into data/papers.sqlite

./gpu_embed.sh user@host st:google/embeddinggemma-2 data/5y   # embeddings on a GPU box over ssh; GPU=MIG-<uuid> pins a device
```

Tests (`tests/conftest.py`) chdir into a temp dir with 60 fake papers from two separable topics, then run the real `compute.py` there. Before every commit, run them. Because the tests tag papers before loading any page, they don't catch fresh-install crashes, so check those against a live `flask run` on an empty data dir.

`eval.py` measures ranking quality. It compares every feature set × model combination by checking where held-out positives land in the ranking.

## Architecture

The pipeline runs in batch through cron jobs, and the web server only reads its results:

1. **`arxiv_daemon.py` / `fetch_papers.py`** (and the bulk importers) write papers to `data/papers.sqlite` with `PapersDB.upsert`, which keeps only the newest version. `aslite/arxiv.py` wraps the arxiv API. `aslite/sources.py` has a `Source` per site papers come from (`ARXIV`, then `OTHERS`: `ACL`, `PMLR`, `JMLR`, `CVF`, `NEURIPS`, `ISCA`; the proceedings sites are `CitationPage`s, read from their citation_* meta tags; ids other than arXiv's and the Anthology's are `<name>:...`, never with a '/'): `find_paper_id` (any link, DOI or id), `source_of(pid)`, `links(pid)` (cards and graph nodes get `url`, `pdf`, `source`, `venue_note` from the server; the app never builds them), `year`, `fetch` (`batch` ids per request inside the source's `slot()`, `db.host_slot`), `license`, `html_url` (None: the enrich daemon reads the PDF). Their papers are stored like arXiv's (`_version` 1, the source's `category`, the venue in `arxiv_journal_ref`, `short_venue` makes "ICML 2023"); only the Anthology's have an open license (CC BY 4.0 from 2016, else BY-NC-SA 3.0), the others get no thumbnails. No paper may be here twice (user request): `fetch_missing` stores a paper that is on arXiv too as the arXiv one and returns the mapping (`twins`): `refs.arxiv_twin` (same title in the titles table or ours), else one arXiv API search by title (`ARXIV.by_title`, counted as a fetch); titles under `SHORT_TITLE` words also need an author in common (`refs.same_paper`). compute.py runs `refs.merge_twins` first: a paper whose arXiv version arrived later is merged into it (saves, reads, notes via `db.move_paper`, citations via `RefsDB.move_paper`). The graph's open box asks `/ui/paper_id` to read a link.
2. **`compute.py`** reads all papers and writes `data/features/`, which loads as a dict with the keys `pids`, `x` (sparse tfidf), `vocab`, `idf`, `x_time` (the paper version each row was made from) and `ptoi` (pid -> row). The vocabulary and idf are learned again only every `REFIT_DAYS`, after `REFIT_GROWTH` more papers, on changed settings or with `--refit`; in between, rows of unchanged papers are taken over from the last features and only new or updated papers are transformed (a full run took ~5 of the 6 minutes on 721k papers). Embeddings add `x_emb` (dense, PCA'd to 256 dims and L2-normalized) and `emb_model`. `aslite/embed.py` produces those embeddings and caches them per paper and model in `data/embeddings.sqlite`, so a rerun only embeds new papers.
3. **`serve.py`** (Flask) and **`send_emails.py`** both rank through **`aslite/rank.py`**. Its `rank(features, pos_pids, neg_pids, feats, model, C)` trains a small linear model on the fly for each request or tag and returns sorted pids, scores and top tfidf words. Nothing is precomputed per user.
   - `feats`: `tfidf | emb | concat | fusion | auto`. Every option except `tfidf` needs `x_emb`, and `auto` falls back to tfidf when it is missing.
   - `model`: `svm` (the original: every untagged paper counts as a negative, up to a random 20k sample on big corpora, and downvotes get extra weight) or `logreg` (Scholar Inbox recipe: random negatives plus S/V class weights).
   - Embeddings can be partial: `embed_daemon.py` fills the cache slowly (duty cycle, priority order), `compute.py --embed_budget` (`EMBED_BUDGET`, 0 in docker) limits its own embedding, and features then carry `emb_mask`. `rank.usable()` says which rows a model can score; masked rows must never be ranked, sampled as random negatives, or counted in z-scores and score sketches. GPU results are merged into the cache (`EmbeddingCache.merge`), never copied over it. Memory: embed_daemon.py never imports torch itself, a spawned worker loads the model per session and exits (deleting a model in-process frees only part of it); compute.py never builds the full-size embedding matrix (`EmbeddingCache.matrix(transform=...)` reduces chunks as they stream in, PCA fitted on a sample) and learns the tfidf vocabulary from a seeded 100k sample (counting all bigrams of 657k papers took 5 GB).
   - `model` also has `lda`: closed-form discriminant analysis on background statistics cached per features (`_bg_stats`), ~5 ms per fit, slightly worse than logreg in eval.py (README), so not the default.
   - `DEFAULT_C` and `DEFAULTS` are untuned starting points, meant to be tuned with `eval.py`.

All file I/O and DB access goes through **`aslite/db.py`**. Scripts don't touch the filesystem directly, so add new storage there.
- Plain SQLite through the stdlib, every database in WAL mode, so the web server keeps reading while the updater writes. The schema is created on first connect (`connect()`). Copy a live database with `snapshot()`, never with `cp`.
- `papers.sqlite`: one row per paper. `venue` is `aslite.arxiv.venue()` of the comment and `journal_ref`, computed on write (`_paper_to_row`) and backfilled once when the column is added; after changing `venue()`, run `PapersDB().recompute_venues()`. serve.py keeps `{pid: venue}` with the paper times (`get_times()[3]`) for the "accepted / published only" filter (`published=yes`). `PapersDB` returns the same paper dicts (`_id`, `_time`, `authors: [{name}]`, `tags: [{term}]`, ...) the code always used, and also has `get_many`, `times` and `search`. Search is an FTS5 index over the table itself, kept in sync by triggers (bm25, weights title > authors > abstract). `search()` drops stopwords and wants every word (prefixes for 3+ letters), falling back to any word below `SEARCH_MIN_ALL` results; bm25 costs time per matching paper, so never OR common words. Typos are fixed by `aslite/spell.py` (`Speller`, words of the index in ≥5 papers, written to `search_terms.json` by compute.py, loaded per worker by `get_speller()`); the page says "Showing results for …" and `exact=yes` searches what was typed. Result cards mark where the search matched (static/app/highlight.js, the CSS Custom Highlight API, so the DOM and KaTeX are untouched; `gvars.highlight` from `search_highlight`): the query's words at word starts, stopwords only inside the query's own phrases with its words on both sides.
- `users.sqlite`: `users` (password hash, email, last_active), `tags` (one row per user/tag/paper, `neg` marks a downvote, so like and downvote are exclusive by construction), `fetches`, `digests` (the latest digest per user), `reads` (papers marked read: the box on saved papers' cards, and the "To read" tab `rank=unread` = saved minus read), `notes` (the user's note per paper, shown only to them; Markdown, rendered by static/app/markdown.js into Preact nodes, never as html; the user's own searches go over them first, `note_matches`, and skip the typo fix for words a note has; agents have `set_note` and `list_notes`), `tokens` (agent access tokens, sha256 only). `models.sqlite`: the cache of trained models, safe to delete. `refs.sqlite`: references of papers (`RefsDB`: `refs`, `fetched` = which papers were tried, `titles` = a hash of every arXiv title, from `import_snapshot.py --titles`). `enrich_daemon.py` fills it and `data/thumbs/` (`db.save_thumb`/`thumb_file`, served by `/thumb/<kind>/<pid>`, `THUMB_KIND` picks figure or page; each also has a big one, `?size=big`, for the view a click on the card opens; arXiv's HTML figures are PNG/JPG, there are no SVGs to take) per paper from up to three arxiv.org requests (HTML, its first figure, the PDF), one per ≥15 s outside `arxiv_slot`'s lock (`aslite/refs.py`: LaTeXML parser, `parse_pdf` for papers without HTML, i.e. before Dec 2023: numbered lists, else author-year ones split at lines starting an entry: `Surname, First`, or names then the year (ACL `… Last. 2019.`, APA `… (2019).`); after a parser change, move `PDF_AUTHOR_YEAR_SINCE` so papers it found no list in can be asked for again on the graph page (`may_reread`), never re-read them all, `Matcher` by id, title table, our titles, title pieces; `aslite/thumbs.py`: Pillow/pypdfium2, untrusted input, failures mean no thumbnail). Thumbnails only for papers under an open license (`thumbs.is_open`, license per paper in `RefsDB.licenses` from `--titles`, else the abstract page; `fetched.license` is what a thumbnail was made under, and `/thumb` checks it): German copyright has no fair use, so arXiv's default license means no thumbnail, and cards credit the license; Search results show how well each fits the owner's tags: `/ui/fit?pids=` (asked for by `PaperList` once the results show, a skeleton chip meanwhile) gives each paper only its best tag and its "top x%" there, from the cached per-tag models. `cited_rank` in serve.py is the Cited tab (`rank=cited`, a rank like saved/down: add new ranks to the same lists in serve.py and static/app/list.js). `metrics.sqlite`: timings for /stats, a week, safe to delete: web workers count request times per kind of page (`aslite/metrics.py`, `g.metric_name`, flushed once a minute), background jobs call `db.put_job` (compute, embed, arxiv, enrich). Never put a user, ip or query in it (privacy.html says so).
- Digest: `aslite/digest.py` computes it (one rank per tag, last N days, minus rated papers). `send_emails.py` stores it and emails it over SMTP; `/digest` shows the stored one with one-click votes; "Load more" per tag fetches `/digest/more` (the tag's Recommended model, cached, over the stored digest's days, minus what the page shows and rated papers). Email links come from `PUBLIC_URL`, never a hardcoded domain. `docker/mail/` is the optional outgoing Postfix + OpenDKIM container.
- `features/<version>/` holds `.npy` arrays that are memory-mapped (all workers share one copy in the page cache), and `features/current` is a symlink swapped atomically. `load_features()` caches per process until `current` changes. Never build a full concat or copy of `x` per process; `rank.py` stacks only the training rows and scores the blocks separately.
- `migrate_db.py` converts the old sqlitedict files (papers.db, dict.db, embeddings.db, features.p). It reads them raw, so sqlitedict is no longer a dependency.
- `load_features()` caches the pickle in memory and reloads it only when the file's mtime changes. `save_features` writes atomically, so `compute.py` can run while the server is up.
- serve.py caches every paper's time in memory per worker (`get_times`, plus `row_times` aligned with the features' rows), and reloads it when papers.sqlite (or its WAL) changes. Never iterate all papers per request, not even to build a list of them. `rank.fit()` returns the model as a dict (coefs plus a score sketch for "top x%"), and `rank.apply()` scores only the rows asked for. compute.py stores rows oldest first, so a time window is a tail slice that `_sel` views without copying (scipy's own csr slice copies). `_model_ranking` filters in numpy and sorts only the best `limit`. `rank.rank()`/`score()` score everything and are for eval.py, the digest and the tag check. Keep products in float32 (a float64 coef upcasts the whole memmap). Static urls carry `?v=<mtime>` and are cached for a year; JSON and html answers are gzipped by `compress` (an /ui/list is ~50 kB, ~17 kB gzipped); static files and thumbnails (`COOKIELESS`) never touch the session, since a refreshed cookie plus `Vary: Cookie` made browsers refetch every script on every visit.
- Nothing slow runs while a page loads. The app shows a page at once and fetches its data; while a ranking that trains a model (`SLOW_RANKS`: tags, pid) is on its way, the list is a skeleton, other lists stay (dimmed) until the next one is there. Trained models are cached (`get_model`: per-process LRU, then `data/models.sqlite`, shared by the workers) under a key of user, tags, variant, `rank.fingerprint()` of the exact training set and the features version, so a model can only ever serve the state it was trained on; never key a model by anything looser. An in-flight map makes concurrent requests wait for one fit. After a vote, `prefit_later()` queues the tag's and 'all''s models for a background thread per worker (debounced, deduplicated, it reads the tags when it runs), so the next page finds them ready (`PREFIT=0` turns it off, as in tests). Any new endpoint that changes likes or downvotes should call `prefit_later()`. Models are erased with their tag or account (`db.delete_models`). Results are also cached per user and query in `_rank_cache` (the key includes the user's tags, so any vote invalidates it), so paging and going back are instant. With `WARM_CACHES=1` (set in compose), a thread per worker keeps features and times loaded, and `load_features`/`get_times` serve the old copy while one thread loads a new one. Tests check pages through their `/ui/` data. Slow loads and actions show the busy bar of static/app/lib.js (`busy(msg)`, `useAction`), saying what they wait for.
- Main flow: navigation is three independent choices: which tag (the chip row, "All tags" = `tags=all`), what (the tabs Recommended `rank=tags` / Saved `rank=saved` / To read `rank=unread` / Not for this tag `rank=down` / Cited `rank=cited`), and over how long (the time window select, default `FOR_YOU_DAYS`). Users with tags land on All tags → Recommended. Chips keep the current tab and window (`chipUrl()`); other tag links go through `tagUrl()`. Search is its own form, model settings are under "Advanced" on ranking pages only. Importing papers needs a tag.

AI summaries: `aslite/summary.py` (prompt, JSON schema, `check` rejects empty or overlong fields and the answer is asked for once more, `html_text` = the LaTeXML main text without references and appendix). Stored per paper in `refs.sqlite` `summaries` (status ok/pending/error, `source` html/pdf/abstract/notext). Three makers: `enrich_daemon.py` from the text it downloads anyway (papers enriched earlier get their HTML fetched once more; `abstract` ones are upgraded), `/summaries` in serve.py for the cards of a logged-in user's page (from the abstract, a thread pool, `claim_summaries` marks them pending so workers don't double up; the page polls), and `send_emails.py`, which prepares the digests `DIGEST_PREPARE_HOURS` before the slot (`--prepare-if-due`; `pending_digest_pids` go first in enrich_daemon.py) and summarizes whatever is still missing from the abstract before mailing. `SUMMARY_MAX_DAY` caps the pages and the daemon, not the mail. Cards get `ai` from `render_pid`; agents get `ai_summary`. Agents (and scripts) get any paper's summary from the `get_summaries` tool (`/api/get_summaries?ids=…`): with a token it fetches papers that aren't here (`fetch_missing`) and starts missing summaries (`serve.request_summaries`, shared with `/summaries`), and answers at once with the rest as `pending` (+ `retry_after`): the caller asks again. Never make a request wait server-side for a model or another slow job: a waiting call holds one of the few gunicorn threads every page needs (user decision; polling instead).

Citation graph: `/graph?pid=` (static/app/graph.js, a box at the top opens another paper by id or link, a force layout in SVG, no library) shows a paper, what it cites and the analyzed papers citing it, from `refs.sqlite` (`/ui/graph`: `graph_nodes`, `RefsDB.edges_among`). x is the year (ordinal, so gaps in time don't stretch it), y the paper's position on the root's topic axis (`topic_axis`: first principal component of the `x_emb` rows of the root and its neighbours, cached in `_axes` per root and features version; `?root=` keeps every later fetch on the same axis). "Ghosts" (`ghosts`, `GHOSTS`, rate kind `rank`) are the papers nearest the selected paper in embedding space that no citation links to it, hung on dotted threads from it (the root's come with `/ui/graph`, any other paper's from `/ui/graph/alike`, cached per paper on the page); clicking one adds it for real. The page is built around what a reader wants from it, as three lenses on the selected paper in the side panel (`lensPicks`): Read first (what it builds on, most cited here first), Came after (papers citing it, newest first, then newer alike ones, since recent papers are barely cited), Siblings (most shared references, then alike in content). A lens lights and numbers its papers on the graph; everything else fades and stays unlabeled. The year is only a pull: crowded years get wider bands (`layoutYears`), papers repel twice as hard sideways, and a collision pass keeps dots from covering each other. Both need embeddings and are skipped without them (caught, the graph still loads). Clicking a paper whose references were read adds its neighbours; one that wasn't is asked for (`POST /graph/analyze`, logged in, `ENRICH_ENABLED` must be on in the web service too, rate kind `analyze`, at most `ANALYZE_QUEUE_MAX` waiting; a paper outside the site is fetched first through `fetch_missing`, so it counts against the fetch limits). Requests go to `refs.sqlite` `requested` (no user stored); `enrich_daemon.py` takes them before anything else (`requested_due`, checked every `ASK_POLL` s while idle and between papers), the page polls until they are read.

Agents: `agents.py` (a Blueprint, `agents.register(serve)` at the end of serve.py, because tests reload serve) registers tools once (`@tool(description, params, access=public|user|write, limit=<RATE_LIMITS kind>, title=, destructive=)`; every tool needs a `title` and `destructive=True` if it can remove or overwrite user data, as Claude's connector directory requires) and serves them over MCP (`POST /mcp`, JSON-RPC, stateless, no SSE), as JSON (`/api`, `/api/<tool>`) and in `/llms.txt`. Tools call serve.py's own rankings (`_ranked`, `get_model`, `_model_ranking`), so they behave like the pages; `rank_like` (a model on given papers, kept in memory only like "similar") is the main research tool. Auth is `Authorization: Bearer asr_...` (`db.create_token`, made on `/agents`): before_request turns it into `g.user` with `g.token` and `g.scope`: `read`, `agent` (tag tools only, every tag forced to `agent:…` by `_writable_tag`, no read marks or notes) or `write`; `g.readonly` unless `write`, so only full tokens reach the site's own POST endpoints; `AGENT_ENDPOINTS` ignore the session cookie, so no web page can call them as its visitor, and tokens can't make tokens. OAuth (for claude.ai's connectors, which can't take a header) is at the end of agents.py: metadata, dynamic registration, authorization code + PKCE S256, public clients only; the token it issues is an ordinary token with `tokens.client` set (a new grant replaces the client's old one). `/mcp/me` is `/mcp` that answers 401 without a token (that 401 is what starts the flow; on `/mcp` a connector would stay anonymous). A localhost redirect uri (Claude Code, possibly on another machine over ssh) gets a page with the callback URL to paste into Claude Code (what it asks for), click, or `curl` there, not a redirect. Never redirect before the client and redirect uri are checked, keep codes single use, and keep the consent page's CSP widening (form-action to the redirect origin) to that page. Paper text and notes are third-party content: the MCP instructions say so, and no tool deletes tags. Add new agent abilities as tools, not new endpoints.

User model: accounts have werkzeug password hashes in `users.sqlite`. The first login with a new username signs up, unless `ALLOW_SIGNUP=0`; usernames with tags but no password (from before passwords) only get one through `flask set-password`. Sessions carry `v`, a hash of the password hash, so a password change or deleted account ends every session in `before_request`. With `PUBLIC_URL` set, it is also the only accepted Host (TRUSTED_HOSTS) and the base of every emailed link. The Flask session is signed with `$SECRET_KEY`, else `secret_key.txt`, else `data/secret_key.txt`, which is generated on first run. Every endpoint that changes state is POST-only, and cross-site POSTs are rejected through SameSite=Lax cookies plus a `Sec-Fetch-Site` check. Keep it that way for new endpoints. Read-only sessions (login with an empty password into an account whose `users.public` is 1) get every POST except login/logout rejected in `before_request`, so new write endpoints are covered automatically; templates and JS hide edit controls via `readonly` / `canEdit`, and the profile never shows the email to them. Expensive endpoints call `rate_limited(kind)` (in-memory token buckets per user or ip, see `RATE_LIMITS`); add a kind for any new expensive path. `TRUST_PROXY` and `SECURE_COOKIES` are for running behind the https proxy. For a given user and tag, a paper is either liked (`/add`) or downvoted (`/addneg`), never both. Shared links: `?u=<name>` on the pages in `SHAREABLE` shows that user's tags if `users.public` is 1; `get_tags()`/`get_neg_tags()`/`get_seen_tags()` read `g.owner` (the page's owner), while every write uses `g.user`, so a link can never write to someone else's account. "Hide rated papers" (`_rated`) hides saved papers everywhere, but downvotes/neutrals only for their own tag; the digest does the same per section. Per-tag digest sizes live in `digest_sizes` (only where they differ from `digest.default_size(tag)`: `PER_TAG`, but 0 for `agent:` tags, which stay out of the digest until the user gives them a number). The digest is sent weekly, but the window it takes papers from is per user (`users.digest_days`, 0 = `db.DIGEST_DAYS`; `db.get_digest_days`), set on the profile with the sizes; `send_emails.py -t` overrides it for everyone.

Reading offline (on a plane, user request: the papers themselves, not just abstracts): `/offline` (static/app/offline.js, "✈ offline" in the header) keeps a pack on the device in Cache Storage `pack-v1`: `/ui/offline` (To read, the latest digest per tag, the best `OFFLINE_FOR_YOU` of For you, as cards with `offline_pdf` state; then up to `OFFLINE_SAVED_MAX` other saved papers, read ones too, as an `extra` section: shown closed, no thumbnails, summaries or PDFs, there so the page's search box (`searchPack`, every non-stopword at a word start, `pack.stopwords` = sklearn's like the server) finds them offline); the digest sections show the digest as sent (`again`: papers in To read too); the page has tabs per list (`PackLists`; offline, the address `/digest` opens the digest tab) and an order (`sorted`: PDF on the device first, as on the site, newest); main papers carry their `refs` (`offline_refs`, at most `OFFLINE_REFS_MAX`), each with a known id savable to a tag offline (`/add`, or `/import` for papers the site lacks; both queue in lib.js's `QUEUEABLE`, a 429 waits for the next flush). PDFs open in the app's own reader (`/read?pid=`, static/app/reader.js, the vendored pdf.js loaded only there; its worker and standard fonts are in `offline_files`, so it works offline): pages drawn near the screen and let go of far from it (at the screen's resolution; while the browser is pinch-zoomed in, the visible part is drawn again at the zoomed one over it, `drawSharp`, as the browser's own viewer does), a text layer for selecting and finding, and our own link layer. A tap on a citation shows its bibliography entry (`textAt`: the text where the link's destination points, cut at the entry's end) matched to the pack's `refs` (`matchRef`), or an arXiv id in it, with "+ Save" to a tag (`saveRef`, shared with the references list); other links inside the paper jump, with ↩ Back; the browser's own viewer stays one tap away ("Browser viewer" in the reader, "browser viewer" on the card, user request), and both offer a copy of the reader's link (`CopyLink` in lib.js), their AI summaries (asked for through `/summaries` until ready), thumbnails, and PDFs. PDFs: `POST /offline/pdfs` records the device's whole set (`users.sqlite` `offline_pdfs`, `db.set_pdfs`: papers left out of it, e.g. read ones, are let go of, so the limit doesn't fill up; at most `OFFLINE_PDF_MAX` per user, rate kind `offline`, needs `ENRICH_ENABLED`), `enrich_daemon.fetch_pdfs` downloads them before its other work (only the graph page's requests go first; one request each at its pace, robots.txt of the proceedings sites) into `data/pdfs` (`db.save_pdf`, `pdfs` table; those papers are enriched next, from that copy: `enrich_daemon.get_pdf` reads a kept PDF instead of downloading it again and keeps one it downloads for someone waiting, so no PDF is fetched twice), `/offline/pdf/<pid>` serves one only to a user who asked for it, and `db.expire_pdfs` deletes requests and files `OFFLINE_KEEP_DAYS` after the last ask (and with the account). The page polls `/ui/offline/pdfs` and copies ready ones to the device. A PDF whose paper leaves the set but stays in the pack (read papers stay in the saved section) isn't deleted from the device but made a light copy there (`lighten` in offline.js, static/app/shrink.js with the vendored pdf-lib, loaded only then), aiming at `TARGET` (200 kB as stored, user request) in `STEPS`, stopping at the first that fits. Nothing is ever left out (user decision: no dropped pages, and a bad JPEG rather than a gray box), so a paper with more than fits keeps its smallest copy above TARGET. Stored packed (`pack`: every stream but images uncompressed, Type 1 fonts' eexec part decrypted, the whole file LZMA'd with the vendored lzma-js; `X-Resanity-Packed`), which takes a third or less of the PDF's own size; sw.js unpacks it (importScripts of the decoder, then the eexec cipher redone) so the reader gets the PDF byte for byte, and shrinkPdf checks that round trip before a copy is kept. Sizes are guessed from native gzip of all but the JPEGs and measured with LZMA when it might fit. Steps: junk out (XMP, `PTEX.InfoDict`s of included figures, which can hold a whole draw.io source, tagging, colour profiles) and images to JPEG; then text fonts left out and drawn as the standard 14 (BaseFont renamed by style, Type 1 encodings spelled out as Differences, composite fonts kept readable by their ToUnicode; never fonts with glyphs beyond `LATIN`: pdfium drew no Δ, ≠ or β without them; small caps only in the last steps), and the numbers of vector drawings rounded to 4 significant digits (`roundNumbers`, relative so it is safe in any coordinate system; 3 in the last steps); then worse images, down to 100 px. Math and symbol fonts (`MATH_FONT`) always stay: without them ≠ turned into = and ∑ vanished in pdfium and pdf.js. Light copies carry the `X-Resanity-Light` header, `LIGHT_BUDGET` for all, oldest dropped first; a paper back in the set gets its full PDF again. `static/app/sw.js` (served as `/sw.js`, `COOKIELESS`) keeps a copy of the app's html and versioned static files; offline.js also writes them (`keepApp`), since the worker only takes over after the first load. Without a network, app.js starts with the last `/ui/me` (localStorage) and every address shows the offline page; votes, read marks and notes go into lib.js's queue (`QUEUEABLE`, localStorage), the stored pack follows them (`onPaperChange`), and `flushChanges` sends them in order once `/ui/me` answers or the `online` event fires. Logging out or deleting the account deletes the pack, the queue and the remembered user (`forgetDevice`), and so does another user logging in on the device (`claimDevice`, `resanity-owner`: a session can end without a logout). Not copyright-checked for arXiv's default license: the PDFs are a private copy for the one user who asked, never shown to anyone else.

Frontend: a client-side app in `static/app/` (Preact + htm as native ES modules, an import map in `static/app/index.html`, no build step). Every page address (`APP_PAGES` in serve.py: `/`, `/digest`, `/profile`, ...) answers with that one html (`shell()`, which stamps `?v=<mtime>` on the `/static` urls and allows the import map by its sha256 in the CSP, so `script-src 'self'` stays strict). Addresses are unchanged, so old links and bookmarks work. `lib.js` has the router (same-origin links to app pages are intercepted, `history.pushState`, scroll restored on back/forward), `api()` (Accept: application/json, errors come back as `{error}`), `useData(path)` (a page's data, cached per address so back is instant, cleared by any POST), the `me` store (`/ui/me`: who is logged in, refreshed after login/logout), `?u=` handling (`shared.owner`, `withOwner`) and the busy bar. `papers.js` has the cards (votes, notes, AI summary tabs, digest sections, tag check), `list.js` the main page (`/ui/list`, the old main(): same query string, plus tags, counts and `gvars`), `pages.js` digest/inspect/stats/text pages, `account.js` profile/import/agents. The `Page` context tells cards what page they are on (rank, tag, whose, canEdit). htm drops whitespace that contains a line break next to a tag, so a space between text and an inline element at a line break needs `${' '}`. Form endpoints answer `{ok: true}` or `{error}` with a status; `wants_json()` decides for the few shared with server pages (`/login` from the oauth consent page still redirects). The text pages are fragments in `templates/pages/` (`/ui/page/<name>`); `base.html` is only the layout of the server pages left (authorize, confirm_email, unsubscribe, error).
