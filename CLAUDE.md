# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

The project is **Arxiv Resanity**, a fork of karpathy's arxiv-sanity-lite. Say "the original arxiv-sanity-lite" only when you mean his version.

## Working rules (from the user, keep these)

- Commit on your own after every substantial change, without waiting to be asked. Use a brief title and explain the reasons in the commit body. Don't push; the user reviews and pushes.
- Whenever the user gives guidance or corrects a mistake, add it to this section so it doesn't happen again, and commit that too.
- Git author is `Dorian Koch <do.ko1605.dk@gmail.com>`, set in the repo's local git config.
- Flag evaluation caveats yourself, as soon as you see them, and fix them before drawing conclusions. Don't sit on a concern you noticed. (Example: the arxiv_daemon background papers are newer than every Scholar Inbox rating, so eval scores against them are inflated. Use `eval.py run --pool rated`.)
- Never hammer arXiv; the user does not want to be banned. Every API call goes through `db.arxiv_slot()` with a timeout and bounded backoff (arxiv_daemon.py once retried empty pages every 0.5 s, forever). Pause ≥3s between API calls (harvest_papers.py uses 5s), honor 503 Retry-After, back off on errors, and don't re-download what is already in papers.sqlite. For bulk data, use the Hugging Face snapshot (import_snapshot.py) instead of arXiv's APIs. Pages on arxiv.org itself (`/html`, `/pdf`, `/abs`) fall under its robots.txt, which asks for `Crawl-delay: 15`: fetch them through `db.arxiv_slot(pause=15)`, and never touch the paths it disallows (`/refs`, `/cits`, `/api`, `/search`, ...).
- arXiv calls a user can trigger (`/import`) must go through `db.arxiv_slot()` (one call per 3.5 s across processes) and count against `FETCH_LIMIT_USER`/`FETCH_LIMIT_TOTAL` via the `fetches` table. Never fetch from a GET handler.
- Anything outward-facing (emails, pushes to other services) is off by default and never fires on first start or right after being enabled; the user turns it on after testing. (The digest once defaulted to on and would have mailed everyone before the DNS records existed.)
- Docker networking: all services share the single external network `arxiv-resanity` (docker-compose.override.yml); services and containers are both named `arxiv_resanity_<x>` (web, updater, mail) so nginx can find them and nothing clashes on the shared network, with underscores, not dashes (user preference; the network keeps its dash). (Renaming only `container_name` wasn't what the user asked for.) (A request for "its own network" meant one network for the project, not one per service.)
- EU law (GDPR/ePrivacy): never load anything from a third-party server in pages (vendor it into static/vendor via update_vendor.py; the CSP enforces it), new email addresses go through the double opt-in (`request_email`/`confirm_email`, never store an unconfirmed address as `email`), and keep templates/privacy.html true whenever you change what is stored, logged or sent anywhere.
- UX: the point of the site is the most relevant recent papers, so users with tags land on "For you" (30 days), not "Newest". No page may block for seconds; slow work loads in the background behind a placeholder that says what is happening. Placeholders are skeletons (a blanked copy of the content that is coming, like React Suspense fallbacks), not spinners (user preference). Every option or filter gets a tooltip plus a visible hint (touch screens), but no badges on things that are plainly clickable (the whole thumbnail opens big, no ⤢ mark on it), and every tag needs a visible list of its saved papers.
- Links that leave the site open in a new tab (common.js sets target=_blank on click for every off-site link, so new links are covered automatically).
- Public profiles (`users.public`, shown as "Public profile", not "sharing"): right after signup, a dialog (base.html, `session['ask_public']`) asks about it with the box ticked; the account stays private until it is answered. That was the user's decision after being told it likely conflicts with Art. 25(2) GDPR (privacy by default) and Planet49 (pre-ticked boxes aren't consent), and asked for a dialog instead of a checkbox on the login form; don't silently flip it back, but don't extend the pattern to other data either.
- Work and commit directly on `master`; don't create feature branches, even if a pasted prompt asks for one.
- Every change to a table that may already exist needs a migration for existing databases (`ALTER TABLE ... ADD COLUMN` under `BEGIN IMMEDIATE`, see `PapersDB._add_columns`, `RefsDB._migrate`) and a test that opens an old one, even if you think the earlier version was never deployed: the user may have pulled any commit (the server ran `refs.sqlite` from an intermediate commit, and every page broke on a missing column). `CREATE TABLE IF NOT EXISTS` never changes an existing table. Lookups that only decorate a page (thumbnails, counts on tabs) catch their errors, so a broken side database can't take the page down.

## Commands

The shell is zsh, which doesn't word-split an unquoted `$VAR`. A command stored in a variable has to be expanded as `${=VAR}`, and a list of ids should be looped over as an array (`for p in ${=P}`). A failed split often shows up only as an empty log.

Never gate a commit on `uv run pytest | tail -1 && git commit`: the pipe returns `tail`'s exit code, so a failing run still commits. Use `uv run pytest -q && git commit ...`, or `setopt pipefail` first.


Dependencies are managed with uv (`pyproject.toml` + `uv.lock`, Python 3.12+, `package = false`). Every script runs from the repo root, because paths such as `data/` and `secret_key.txt` are relative to it.

```bash
uv sync                                    # core + dev (pytest); --extra embed|serve|bulk|thumbs for optional deps
uv sync --extra embed                      # sentence-transformers for compute.py --embed_model st:...
                                           # (uv sync drops extras you don't list, so pass every one you need)
uv run pytest                              # smoke tests, synthetic corpus in a temp dir, no network
uv run ruff check . && uv run ruff format . # lint (bug-finding rules) + format; run both before committing
uv run pytest tests/test_rank.py -k logreg # single test

uv run python arxiv_daemon.py --num 2000   # pull new papers from the arxiv API into data/papers.sqlite
uv run python compute.py                   # rebuild data/features/ (tfidf); add --embed_model to also embed
uv run python fetch_papers.py <arxiv ids>  # add specific papers by id, then rerun compute.py
ARXIV_SANITY_DATA=data/5y uv run python import_snapshot.py --years 5 --check data/papers.sqlite   # bulk import from the HF snapshot (extra bulk), verified; no arXiv load
ARXIV_SANITY_DATA=data/5y uv run python harvest_papers.py --years 5   # fallback: same via OAI-PMH, ~5h of polite requests
./gpu_embed.sh user@host st:google/embeddinggemma-2 data/5y   # embeddings on a GPU box over ssh; GPU=MIG-<uuid> pins a device
uv run flask --app serve run               # web UI (make fun); `make up` = daemon + compute
docker network create --ipv6=false arxiv-resanity   # once: docker-compose.override.yml puts all services on it
docker compose up -d --build               # public deployment: gunicorn web + daily updater, behind an https proxy (.env.example)
uv run flask --app serve set-password <user>   # create/reset an account (needed when ALLOW_SIGNUP=0)
uv run python send_emails.py --dry-run 1 -u <user> --save d.html   # compose (and store) a digest without sending
uv run python enrich_daemon.py --once     # references + thumbnails of saved/digest papers (extra enrich)
uv run python eval.py run --source tags    # compare ranking variants on held-out liked papers
```

Tests (`tests/conftest.py`) chdir into a temp dir with 60 fake papers from two separable topics, then run the real `compute.py` there. Before every commit, run them. Because the tests tag papers before loading any page, they don't catch fresh-install crashes, so check those against a live `flask run` on an empty data dir.

`eval.py` measures ranking quality. It compares every feature set × model combination by checking where held-out positives land in the ranking.

## Architecture

The pipeline runs in batch through cron jobs, and the web server only reads its results:

1. **`arxiv_daemon.py` / `fetch_papers.py`** (and the bulk importers) write papers to `data/papers.sqlite` with `PapersDB.upsert`, which keeps only the newest version. `aslite/arxiv.py` wraps the arxiv API.
2. **`compute.py`** reads all papers and writes `data/features/`, which loads as a dict with the keys `pids`, `x` (sparse tfidf), `vocab`, `idf` and `ptoi` (pid -> row). Embeddings add `x_emb` (dense, PCA'd to 256 dims and L2-normalized) and `emb_model`. `aslite/embed.py` produces those embeddings and caches them per paper and model in `data/embeddings.sqlite`, so a rerun only embeds new papers.
3. **`serve.py`** (Flask) and **`send_emails.py`** both rank through **`aslite/rank.py`**. Its `rank(features, pos_pids, neg_pids, feats, model, C)` trains a small linear model on the fly for each request or tag and returns sorted pids, scores and top tfidf words. Nothing is precomputed per user.
   - `feats`: `tfidf | emb | concat | fusion | auto`. Every option except `tfidf` needs `x_emb`, and `auto` falls back to tfidf when it is missing.
   - `model`: `svm` (the original: every untagged paper counts as a negative, up to a random 20k sample on big corpora, and downvotes get extra weight) or `logreg` (Scholar Inbox recipe: random negatives plus S/V class weights).
   - Embeddings can be partial: `embed_daemon.py` fills the cache slowly (duty cycle, priority order), `compute.py --embed_budget` (`EMBED_BUDGET`, 0 in docker) limits its own embedding, and features then carry `emb_mask`. `rank.usable()` says which rows a model can score; masked rows must never be ranked, sampled as random negatives, or counted in z-scores and score sketches. GPU results are merged into the cache (`EmbeddingCache.merge`), never copied over it. Memory: embed_daemon.py never imports torch itself, a spawned worker loads the model per session and exits (deleting a model in-process frees only part of it); compute.py never builds the full-size embedding matrix (`EmbeddingCache.matrix(transform=...)` reduces chunks as they stream in, PCA fitted on a sample) and learns the tfidf vocabulary from a seeded 100k sample (counting all bigrams of 657k papers took 5 GB).
   - `model` also has `lda`: closed-form discriminant analysis on background statistics cached per features (`_bg_stats`), ~5 ms per fit, slightly worse than logreg in eval.py (README), so not the default.
   - `DEFAULT_C` and `DEFAULTS` are untuned starting points, meant to be tuned with `eval.py`.

All file I/O and DB access goes through **`aslite/db.py`**. Scripts don't touch the filesystem directly, so add new storage there.
- Plain SQLite through the stdlib, every database in WAL mode, so the web server keeps reading while the updater writes. The schema is created on first connect (`connect()`). Copy a live database with `snapshot()`, never with `cp`.
- `papers.sqlite`: one row per paper. `venue` is `aslite.arxiv.venue()` of the comment and `journal_ref`, computed on write (`_paper_to_row`) and backfilled once when the column is added; after changing `venue()`, run `PapersDB().recompute_venues()`. serve.py keeps `{pid: venue}` with the paper times (`get_times()[3]`) for the "accepted / published only" filter (`published=yes`). `PapersDB` returns the same paper dicts (`_id`, `_time`, `authors: [{name}]`, `tags: [{term}]`, ...) the code always used, and also has `get_many`, `times` and `search`. Search is an FTS5 index over the table itself, kept in sync by triggers (bm25, weights title > authors > abstract). `search()` drops stopwords and wants every word (prefixes for 3+ letters), falling back to any word below `SEARCH_MIN_ALL` results; bm25 costs time per matching paper, so never OR common words. Typos are fixed by `aslite/spell.py` (`Speller`, words of the index in ≥5 papers, written to `search_terms.json` by compute.py, loaded per worker by `get_speller()`); the page says "Showing results for …" and `exact=yes` searches what was typed.
- `users.sqlite`: `users` (password hash, email, last_active), `tags` (one row per user/tag/paper, `neg` marks a downvote, so like and downvote are exclusive by construction), `fetches`, `digests` (the latest digest per user), `reads` (papers marked read: the box on saved papers' cards, and the "To read" tab `rank=unread` = saved minus read), `notes` (the user's note per paper, shown only to them), `tokens` (agent access tokens, sha256 only). `models.sqlite`: the cache of trained models, safe to delete. `refs.sqlite`: references of papers (`RefsDB`: `refs`, `fetched` = which papers were tried, `titles` = a hash of every arXiv title, from `import_snapshot.py --titles`). `enrich_daemon.py` fills it and `data/thumbs/` (`db.save_thumb`/`thumb_file`, served by `/thumb/<kind>/<pid>`, `THUMB_KIND` picks figure or page; each also has a big one, `?size=big`, for the view a click on the card opens; arXiv's HTML figures are PNG/JPG, there are no SVGs to take) per paper from up to three arxiv.org requests (HTML, its first figure, the PDF), one per ≥15 s outside `arxiv_slot`'s lock (`aslite/refs.py`: LaTeXML parser, `parse_pdf` for numbered lists, `Matcher` by id, title table, our titles, title pieces; `aslite/thumbs.py`: Pillow/pypdfium2, untrusted input, failures mean no thumbnail). Thumbnails only for papers under an open license (`thumbs.is_open`, license per paper in `RefsDB.licenses` from `--titles`, else the abstract page; `fetched.license` is what a thumbnail was made under, and `/thumb` checks it): German copyright has no fair use, so arXiv's default license means no thumbnail, and cards credit the license; `cited_rank` in serve.py is the Cited tab (`rank=cited`, a rank like saved/down: add new ranks to the same lists in serve.py, index.html and paper_list.js). `metrics.sqlite`: timings for /stats, a week, safe to delete: web workers count request times per kind of page (`aslite/metrics.py`, `g.metric_name`, flushed once a minute), background jobs call `db.put_job` (compute, embed, arxiv, enrich). Never put a user, ip or query in it (privacy.html says so).
- Digest: `aslite/digest.py` computes it (one rank per tag, last N days, minus rated papers). `send_emails.py` stores it and emails it over SMTP; `/digest` shows the stored one with one-click votes. Email links come from `PUBLIC_URL`, never a hardcoded domain. `docker/mail/` is the optional outgoing Postfix + OpenDKIM container.
- `features/<version>/` holds `.npy` arrays that are memory-mapped (all workers share one copy in the page cache), and `features/current` is a symlink swapped atomically. `load_features()` caches per process until `current` changes. Never build a full concat or copy of `x` per process; `rank.py` stacks only the training rows and scores the blocks separately.
- `migrate_db.py` converts the old sqlitedict files (papers.db, dict.db, embeddings.db, features.p). It reads them raw, so sqlitedict is no longer a dependency.
- `load_features()` caches the pickle in memory and reloads it only when the file's mtime changes. `save_features` writes atomically, so `compute.py` can run while the server is up.
- serve.py caches every paper's time in memory per worker (`get_times`, plus `row_times` aligned with the features' rows), and reloads it when papers.sqlite (or its WAL) changes. Never iterate all papers per request, not even to build a list of them. `rank.fit()` returns the model as a dict (coefs plus a score sketch for "top x%"), and `rank.apply()` scores only the rows asked for. compute.py stores rows oldest first, so a time window is a tail slice that `_sel` views without copying (scipy's own csr slice copies). `_model_ranking` filters in numpy and sorts only the best `limit`. `rank.rank()`/`score()` score everything and are for eval.py, the digest and the tag check. Keep products in float32 (a float64 coef upcasts the whole memmap). Static urls carry `?v=<mtime>` and are cached for a year.
- Nothing slow runs while a page loads. Rankings that train a model (`SLOW_RANKS`: tags, pid) return the page at once with `gvars.pending`, and `Results` in paper_list.js fetches the same URL with `&format=json`. When every model a tags page needs is already cached (`models_ready`, the usual case after the refit that follows a vote), the page ranks right away and ships its results, without the placeholder and second request. Trained models are cached (`get_model`: per-process LRU, then `data/models.sqlite`, shared by the workers) under a key of user, tags, variant, `rank.fingerprint()` of the exact training set and the features version, so a model can only ever serve the state it was trained on; never key a model by anything looser. An in-flight map makes concurrent requests wait for one fit. After a vote, `prefit_later()` queues the tag's and 'all''s models for a background thread per worker (debounced, deduplicated, it reads the tags when it runs), so the next page finds them ready (`PREFIT=0` turns it off, as in tests). Any new endpoint that changes likes or downvotes should call `prefit_later()`. Models are erased with their tag or account (`db.delete_models`). Results are also cached per user and query in `_rank_cache` (the key includes the user's tags, so any vote invalidates it), so paging and going back are instant. With `WARM_CACHES=1` (set in compose), a thread per worker keeps features and times loaded, and `load_features`/`get_times` serve the old copy while one thread loads a new one. Tests that check ranked papers have to use `format=json`. Other slow navigations get the `showBusy` indicator from common.js; forms say what they wait for with `data-busy`.
- Main flow: navigation is three independent choices: which tag (the chip row, "All tags" = `tags=all`), what (the tabs Recommended `rank=tags` / Saved `rank=saved` / To read `rank=unread` / Not for this tag `rank=down` / Cited `rank=cited`), and over how long (the time window select, default `FOR_YOU_DAYS`). Users with tags land on All tags → Recommended. Chips keep the current tab and window (`chipUrl()`); other tag links go through `tagUrl()`. Search is its own form, model settings are under "Advanced" on ranking pages only. Importing papers needs a tag.

Agents: `agents.py` (a Blueprint, `agents.register(serve)` at the end of serve.py, because tests reload serve) registers tools once (`@tool(description, params, access=public|user|write, limit=<RATE_LIMITS kind>)`) and serves them over MCP (`POST /mcp`, JSON-RPC, stateless, no SSE), as JSON (`/api`, `/api/<tool>`) and in `/llms.txt`. Tools call serve.py's own rankings (`_ranked`, `get_model`, `_model_ranking`), so they behave like the pages; `rank_like` (a model on given papers, kept in memory only like "similar") is the main research tool. Auth is `Authorization: Bearer asr_...` (`db.create_token`, made on `/agents`): before_request turns it into `g.user` with `g.token` and `g.scope`: `read`, `agent` (tag tools only, every tag forced to `agent:…` by `_writable_tag`, no read marks or notes) or `write`; `g.readonly` unless `write`, so only full tokens reach the site's own POST endpoints; `AGENT_ENDPOINTS` ignore the session cookie, so no web page can call them as its visitor, and tokens can't make tokens. OAuth (for claude.ai's connectors, which can't take a header) is at the end of agents.py: metadata, dynamic registration, authorization code + PKCE S256, public clients only; the token it issues is an ordinary token with `tokens.client` set (a new grant replaces the client's old one). `/mcp/me` is `/mcp` that answers 401 without a token (that 401 is what starts the flow; on `/mcp` a connector would stay anonymous). A localhost redirect uri (Claude Code, possibly on another machine over ssh) gets a page with the callback URL to paste into Claude Code (what it asks for), click, or `curl` there, not a redirect. Never redirect before the client and redirect uri are checked, keep codes single use, and keep the consent page's CSP widening (form-action to the redirect origin) to that page. Paper text and notes are third-party content: the MCP instructions say so, and no tool deletes tags. Add new agent abilities as tools, not new endpoints.

User model: accounts have werkzeug password hashes in `users.sqlite`. The first login with a new username signs up, unless `ALLOW_SIGNUP=0`; usernames with tags but no password (from before passwords) only get one through `flask set-password`. Sessions carry `v`, a hash of the password hash, so a password change or deleted account ends every session in `before_request`. With `PUBLIC_URL` set, it is also the only accepted Host (TRUSTED_HOSTS) and the base of every emailed link. The Flask session is signed with `$SECRET_KEY`, else `secret_key.txt`, else `data/secret_key.txt`, which is generated on first run. Every endpoint that changes state is POST-only, and cross-site POSTs are rejected through SameSite=Lax cookies plus a `Sec-Fetch-Site` check. Keep it that way for new endpoints. Read-only sessions (login with an empty password into an account whose `users.public` is 1) get every POST except login/logout rejected in `before_request`, so new write endpoints are covered automatically; templates and JS hide edit controls via `readonly` / `canEdit`, and the profile never shows the email to them. Expensive endpoints call `rate_limited(kind)` (in-memory token buckets per user or ip, see `RATE_LIMITS`); add a kind for any new expensive path. `TRUST_PROXY` and `SECURE_COOKIES` are for running behind the https proxy. For a given user and tag, a paper is either liked (`/add`) or downvoted (`/addneg`), never both. Shared links: `?u=<name>` on the pages in `SHAREABLE` shows that user's tags if `users.public` is 1; `get_tags()`/`get_neg_tags()`/`get_seen_tags()` read `g.owner` (the page's owner), while every write uses `g.user`, so a link can never write to someone else's account. "Hide rated papers" (`_rated`) hides saved papers everywhere, but downvotes/neutrals only for their own tag; the digest does the same per section. Per-tag digest sizes live in `digest_sizes` (only where they differ from `digest.PER_TAG`).

Frontend: Jinja templates in `templates/` plus plain-JS rendering in `static/*.js`. `serve.py` passes data to the page through `context['gvars']`, which carries things like the paper list and the `has_emb` flag.
